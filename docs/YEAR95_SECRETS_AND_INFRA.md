Configuração de validação JWT/Auth no backend.\n\n## Backend\nPORT\nNODE_ENV\nCORS_ORIGINS\nTRUST_PROXY\nRATE_LIMIT_MAX\nRATE_LIMIT_HEAVY_MAX\nOBSERVABILITY_LOGS\n\n## AI — fase posterior\nGEMINI_API_KEY\nGEMINI_MODEL\nGEMINI_TIMEOUT_MS\n\n## Market data\nBinance público não precisa de API key para os endpoints públicos de candles/market data usados no MVP.\n\n## IG — fase posterior\nIG_API_BASE_URL\nIG_API_KEY\nIG_USERNAME\nIG_PASSWORD\nSomente ambiente demo inicialmente.\n\n## Saxo — fase posterior\nSAXO_ENVIRONMENT\nSAXO_CLIENT_ID\nSAXO_CLIENT_SECRET\nSAXO_REDIRECT_URI\nSAXO_ACCESS_TOKEN\nAcesso live deve ter flag explícita e continuar read-only até gate separado.\n\n## Infraestrutura\nSupabase: PostgreSQL e Auth.\nRender: API/backend inicialmente.\nCloudflare: DNS, domínio, edge e frontend/Pages quando escolhido.\nVercel: não é dependência estrutural.\n\n## Sequência\n1. secrets locais;\n2. config validation;\n3.
